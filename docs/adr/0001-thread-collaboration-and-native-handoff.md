# ADR-001：转向 `#thread` 团队 Agent 协作对话板与原工具 Worktree 交接

## 状态

Accepted：由用户在规划评审中拍板确认（取代早期云端 Docker 沙箱单仓库自动修复方向；旧规格已归档至 [docs/archive/cloud-sandbox-v0/](../archive/cloud-sandbox-v0/)）。

部分被取代：决策内容第 1 条的 `#thread` 协作载体已由 [ADR-002](0002-inbox-cards-instead-of-chat.md) 的事项卡 inbox 取代；第 2 至 5 条继续有效，其中“读取 `#thread` 上下文”按事项卡的请求、附带上下文与往来记录理解。人与 Personal Agent 分别拥有可寻址身份的设定已由 [ADR-003](0003-cards-addressed-to-people.md) 取代：事项卡发给人，接收人一键交给自己的 Agent；第 2 条的手动唤起由接收人在自己工具中按回车完成。

## 背景

早期草案（`cloud-sandbox-v0`）假设在服务端用 Docker 容器托管运行云端 Agent 自动修 bug。但团队日常已经广泛使用各自的 Personal Agent（Claude Code、Codex、Cursor 等），真正的痛点是：**跨人、跨 Agent 协作时，人被迫充当上下文搬运工，在不同聊天窗口和本地终端之间反复复制粘贴需求、背景和结果**。

同时，若平台试图在后台黑盒托管所有 runtime 或每句话都自动唤醒模型，既会造成配额暗耗与未授权改代码风险，也会让开发者失去在原编码工具中接手操作的控制感。

## 决策内容

1. **一件事一个 `#thread`，人机同场可 `@`：** 采用类似 `#订单列表退款状态` 的 `#thread` 组织协作。人与各自的 Personal Agent 拥有稳定身份，人有权读的 `#thread` 消息其 Agent 默认可读。普通问答直接在 `#thread` 引用消息回复，不强制建任务卡。
2. **`@Agent` 响应默认由所有者手动唤起（R1 拍板）：** 收到 `@B-Agent` 请托时，平台不后台静默跑 LLM，也不允许未批准前读写仓库；由所有者 B 点击唤起本地客户端读取 `#thread` 上下文并生成回答或执行方案。
3. **拉起原生可见会话优先，不以“插入已打开的既有活跃 session”为阻塞项（R2 拍板）：** 只要获批工作能拉起一个带原生 session ID、本人在原客户端可 `attach` 或 `resume` 继续操作的真实会话，并将状态与结果回传原 `#thread`，即满足核心交接要求。
4. **本地 `attempt_id` 持久化与重连核对防重（R3 拍板）：** 每次执行尝试生成唯一 `attempt_id` 并先落盘本地适配器与 worktree 元数据；断线恢复先核对本地是否已有对应会话，杜绝重复开出两个会话改代码。
5. **用 `git worktree` 隔离代码执行，并全程透明展示派生来源（R4 拍板）：** 每次代码执行尝试由本地适配器从主仓库的批准基线派生独立 `git worktree` 与工作分支；在确认单、状态卡和交接页清晰展示**主仓库路径、基线分支与 commit、worktree 本地目录、工作分支名及最新变更 commit**。

## 考虑的替代方案

1. **继续做云端 Docker 沙箱托管平台：** 脱离开发者本地已配好的 coding 工具、个人习惯与本地环境，且无法在原工作台无缝接手，已放弃并归档。
2. **后台全自动监听每条消息并自动执行：** 配额消耗不可控，且违背“真正执行须所有者点头”的安全边界。
3. **必须把任务塞进已打开的 GUI 既有活跃窗口才算成功：** 受限于各客户端 preview 接口与桌面 UI 刷新机制，会把非核心技术限制变成 MVP 阻塞项。

## 影响与取舍

- **正面影响：** 消除了跨人协作时手工复制上下文的摩擦；保留了开发者在原工具（Claude Code / Codex 等）的完整控制权；通过透明的 `git worktree` 派生链路解决了同一仓库并发协助时的工作区冲突。
- **取舍与限制：** 手动唤起意味着所有者 B 离线时发起人 A 需要等待 B 点击唤起；每个任务派生独立 worktree 需要本地磁盘空间，且最终合并回主分支仍由开发者在原工具或通过 PR 完成，平台不自动 merge。
